# АУДИТ ИСХОДНОГО КОДА

## ЦЕЛЬ

Запуск субагента **find-backdoors** для полного аудита исходного кода проекта:
- Недекларированные возможности
- Бэкдоры
- Загрузка стейджеров / дропперов
- Отправка реверс-шеллов
- Деплой веб шеллов
- Эксфильтрация данных из системы
- Обфусцированные части кода
- Динамически собираемые части кода

## ОБЯЗАТЕЛЬНЫЕ ДЕЙСТВИЯ

1. Сразу делегируй задачу субагенту — не выполняй аудит в основном чате. Используй явный вызов:
    ```
    /find-backdoors
    ```
    Субагент описан в `$HOME/.cursor/agents/find-backdoors.md`. Следуй его инструкциям и формату отчёта из этого файла.

2. Передай контекст из аргументов команды (если пользователь указал путь, ветку или файлы после `/audit-source-code`):
   - Ограничь область сканирования указанными путями
   - Учти дополнительные требования пользователя

3. Дождись завершения субагента (синхронно, не в фоне). Итоговый отчёт верни пользователю на русском языке, сохранив структуру находок (тип, риск, файл, строка, рекомендация).

4. Если субагент недоступен (ошибка, лимит плана, не найден в `$HOME/.cursor/agents/`):
   - Сообщи об этом явно
   - Не выдумывай результаты аудита
   - Предложи проверить наличие файла агента и при необходимости переименовать в `find-backdoors.md` с полем `name: find-backdoors` в frontmatter.

## ЗАПРЕЩЕНО

- Пропускать делегирование и «симулировать» аудит по памяти
- Безвозвратно удалять файлы в ходе аудита
- Выполнять опасные shell/git-операции без явного подтверждения пользователя

## ОЖИДАЕМЫЙ РЕЗУЛЬТАТ

Секция **Сводка аудита** по шаблону субагента: количество файлов, находки по уровням (Критический / Высокий / Средний / Низкий), вердикт — можно ли безопасно запускать/собирать проект
